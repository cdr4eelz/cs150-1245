ise-to-vivado

** It seems like the Arty-A7-100 board is recognized best by older Vivado versions. Currently, 2019 seems the best for recognizing the board in the repo, and also PMODs potentially involved. On an Arty, the key PMOD is the RGB (dual PMOD) dealio. Also, not that the Arty board also maps an existing UART to the PL fabric, so it seems that the extra USB-UART PMOD is unnecessary! It would be cool to make the PYNQ work out, but the DDR3_SDRAM via Zynq ARM CPU AXI4 interface (mysterious setup) makes it difficult unless living with BLOCKRAM or "SPRITES-ONLY" or whatever.


Every tool, script, and IP is different between ISE and Vivado. Makefiles can be used, but generally they share their role with TCL scripts.

Migration will attempt this approach:
	Branch "ISE-XUP" off "MASTER" to preserve the last shared state that uses ISE software & XUP hardware.
	Temporary branch "VivadoPynq" forked
	Replace various build steps with Vivado and potentially Verilator, etc.
	Start with a working example (or modern cs151 template) then merge in old code.
	
[ Migration ISE -> Vivado guide ]
https://www.xilinx.com/support/documents/sw_manuals/xilinx2022_1/ug911-vivado-migration.pdf
	
Trying various Vivado versions in order to match examples, PMOD "tested" platforms, etc.
    2018.2 (mentioned for PMODs VGA with ARTY A7-100 sample project! Perfect match to tutorial)
    2019.1 (MIG seems to work)
    2021.2 (??? Examples in this one???)
    2024.2 (latest, hopefully functional. Could upgrade other project to this safely?)

3. Apply the following command in the Tcl Console of Vivado to create the IP:
  create_ip -name mig_7series -version <latest version> -vendor xilinx.com -library ip-module_name <component_name>
For example,
  create_ip -name mig_7series -version 4.1 -vendor xilinx.com -library ip -module_name mig_7series_0
4. Apply the following command to generate the core with the previous MIG project settings:
  set_property CONFIG.XML_INPUT_FILE {<absolute path of the old core mig.prj>} [get_ips <ip_name>]
For example,
  set_property CONFIG.XML_INPUT_FILE {/proj/mig/users/coregen_core/mig_7series_v4_1/mig.prj} [get_ips mig_7series_0]


=== TIMING TOPICS ===
If you want to set all paths between two clock domains:
    set_false_path -from [get_clocks ] -to [get_clocks ]
Because you want to set false paths from i/o ports,use
    set_false_path -from [get_ports FanControl_PWM]
    set_false_path -from [get_ports FanControl_Tacho]
